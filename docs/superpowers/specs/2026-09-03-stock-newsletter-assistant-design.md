# 증권 뉴스레터 도우미 — 설계 문서

- 작성일: 2026-09-03
- 대상 사용자: 증권/주식 유튜버 (비개발자)
- 목적: 매일 아침 각 증권사 리서치 자료를 수집·분석해 "뉴스가 될 만한" 항목을 추천받고, 선택한 내용을 불릿 형식 뉴스레터로 만들어 본인 카카오톡("나와의 채팅")으로 보낸다.

---

## 1. 개요와 범위

### 다루는 정보
- **A. 리서치 리포트** — 증권사 리서치센터 발행 종목/산업 리포트
- **C. 시황 코멘트** — 증권사 시황·마감 브리핑
- **D. 목표주가·투자의견 변경** — 목표가 상향/하향, 투자의견 변경, 신규 커버리지

### 자료 출처 (2곳)
- 네이버 금융 리서치 (`finance.naver.com/research/`) — 종목분석 / 산업분석 / 시황정보
- 한경 컨센서스 (`consensus.hankyung.com`)

### 채널 관심 범위
국내 주식 + 미국 주식 + 섹터 + 시황/매크로 + 개별 종목 (전방위). 범위를 좁히지 않는다.

### "뉴스감" 판단 기준 (사용자 확정)
1. 서로 다른 증권사가 **동시에 같은 종목/업종을 언급** (2곳 이상)
2. 사용자가 등록한 **관심 종목(워치리스트)**에 해당

### 진행 방식: 반자동 (방향 2)
프로그램이 수집·추천 목록 생성 → 사용자가 모바일 화면에서 검토·선택 → 선택분만 뉴스레터로 정리 → 카카오톡 전송.

### 최종 결과물 전달처
본인 카카오톡 **"나와의 채팅"** 에게만. (구독자 단체 발송은 범위 밖. 필요 시 별도 프로젝트.)

### 목표 완료 시각
매일 오전 8시 이전에 사용자가 검토를 마칠 수 있도록. 수집은 사용자가 앱을 여는 순간(대개 7시대) 실행.

## 2. 아키텍처

### 형태
모바일 최적화 **웹앱 1개**. 네이티브 앱 설치 없음. 휴대폰 브라우저로 접속하고 홈 화면에 아이콘 추가(PWA 수준의 manifest만, 오프라인 기능은 불필요).

### 구성 요소
| 구성 | 역할 |
|---|---|
| 프론트엔드(화면) | 추천 목록, 뉴스레터 초안, 관심종목 관리 UI |
| 수집 API(서버 함수) | 네이버·한경 HTML을 서버에서 가져와 파싱 후 정규화된 JSON 반환 (브라우저 CORS 우회 목적) |

### 기술 스택
- **Next.js (App Router) + TypeScript**, Vercel 배포
- HTML 파싱: `cheerio`
- 테스트: `vitest`
- **LLM/AI API 사용 안 함.** 추천은 규칙 기반, 뉴스레터는 템플릿 기반.
- **데이터베이스 없음.** 관심종목·일일 스냅샷은 브라우저 `localStorage`에만 저장.

### 배포/비용
- Vercel 무료 플랜. 사용자가 무료 Vercel 계정 생성 필요(카드 등록 불필요). 배포는 개발자가 안내.
- 운영 비용 0원 (AI 미사용, DB 없음, 무료 호스팅 범위 내).

### 카카오톡 전송 방식 (중요 — 설계 논의 대비 단순화)
- 논의 단계에서는 "카카오 메시지 API의 200자 제한 → 요약+링크 전송"을 가정했으나,
- **실제 구현은 휴대폰 OS 공유 시트(Web Share API, `navigator.share`)를 사용한다.**
  - "[카톡으로 보내기]" 버튼 → 휴대폰 공유 시트 → 카카오톡 선택 → "나와의 채팅" 선택 → 전송
  - 실제 카톡 "메시지"로 전송되므로 **길이 제한이 사실상 없음 → 뉴스레터 전문을 그대로 전송 가능. 별도 링크 불필요.**
  - **카카오 개발자 앱 등록/JavaScript 키/도메인 등록/토큰 관리 전부 불필요.**
- Web Share API 미지원 브라우저(주로 데스크톱)에서는 버튼이 "[전체 복사]"로 폴백. 복사는 항상 동작.

## 3. 화면 구성

하단 탭 3개로 이동. 모바일 세로 화면 기준.

### 화면 ① 오늘의 추천 (메인, 기본 탭)
- 상단: 오늘 날짜, **[새로고침]** 버튼(그 순간 수집 실행), 마지막 수집 시각 표시
- 앱을 열었을 때 마지막 수집이 30분 이상 지났으면 자동으로 1회 수집
- **추천 항목 리스트**. 각 항목:
  - 체크박스 + 종목명(강조) + 태그들 + 대표 코멘트 1줄 + 대표 증권사
  - 예:
    ```
    ☐ 삼성전자   [관심종목] [목표가 상향] [언급 4곳]
      "3분기 실적 컨센 상회, 메모리 업사이클 진입" — 삼성증권
    ```
  - 항목을 펼치면 그 종목에 대한 리포트 전체(증권사별 제목·목표가·링크) 표시
- **정렬**: 관심종목 → 언급 증권사 수 내림차순 → 종목명
- **[전체 보기] 토글**: 숨겨진(언급 1곳·관심종목 아님·특이 태그 없음) 항목까지 표시
- 하단 영역: **카톡방 내용 붙여넣기** 텍스트 칸 + **[분석에 포함]** 버튼
  - 포함 시 리스트에 반영. 기존 종목과 겹치면 `단톡방 언급` 태그 추가.
  - 리스트에 없던 종목이면 "단톡방 발" 별도 섹션에 표시.
  - 종목명을 못 뽑으면 원문을 "단톡방 원문"으로 보관(뉴스레터에 첨부 가능).
- 하단 고정 버튼: **[선택한 항목으로 뉴스레터 만들기]** → 화면 ②로 이동

### 화면 ② 뉴스레터 초안
- 화면 ①에서 체크한 항목이 불릿 형식으로 자동 조립(§5 형식)
- 편집 가능한 텍스트 영역 (문구 직접 수정)
- 버튼: **[전체 복사]**, **[카톡으로 보내기]**
- 마지막으로 생성한 초안은 localStorage에 보관(앱 재방문 시 복원)

### 화면 ③ 관심종목
- 관심종목 리스트: 종목명 입력 후 추가 / 스와이프 또는 삭제 버튼으로 제거
- **[내보내기] / [불러오기]**: 줄바꿈으로 구분된 텍스트로 백업·복원
- 여기 등록된 종목은 화면 ①에서 항상 표시되고 최상단, `관심종목` 태그

### 화면 흐름
① 열기 → (자동/수동)새로고침 → 추천 검토 + 카톡방 내용 붙여넣기 → 항목 체크 → ② 초안 확인·수정 → 복사 또는 카톡 전송. 목표 소요 2~4분.

## 4. 자료 수집 & 추천 로직

### 4.1 수집 (앱을 여는 순간 / [새로고침] 시)
서버 API `/api/collect` 가 아래를 수행:

| 출처 | 페이지 | 추출 항목 |
|---|---|---|
| 네이버 리서치 | 종목분석 목록 | 종목명, 리포트 제목, 증권사, 목표가, 작성일, 링크 |
| 네이버 리서치 | 산업분석 목록 | 업종/제목, 증권사, 작성일, 링크 |
| 네이버 리서치 | 시황정보 목록 | 제목, 증권사, 작성일, 링크 |
| 한경 컨센서스 | 리포트 목록 | 종목명, 제목, 증권사, 목표가, 투자의견, 작성일, 링크 |

- **수집 범위**: 발행일이 오늘 또는 어제인 항목
- **정규화**: 아래 `ResearchItem` 형태로 통일
  ```
  ResearchItem {
    stock: string          // 종목/업종명 (정규화: 공백·괄호 제거, 대표 표기로 통일)
    title: string          // 리포트 제목
    brokerage: string      // 증권사명 (정규화: "미래에셋증권"→"미래에셋" 등 표준화 테이블)
    targetPrice?: number
    opinion?: string        // 매수/중립 등
    date: string            // YYYY-MM-DD
    sourceSite: "naver" | "hankyung"
    sourceUrl: string
    kind: "company" | "industry" | "market"   // 종목 / 산업 / 시황
  }
  ```
- **중복 제거**: `stock + brokerage + 제목 유사도(정규화 후 부분일치)` 가 같으면 한 건으로 병합, 링크는 둘 다 보관.
- 한쪽 출처 실패 시 나머지로 진행 + 실패 출처 표시. 둘 다 실패 시 오류 안내.

### 4.2 추천 점수/태그 (규칙 기반, `kind === "company"` 대상)
종목명 기준으로 그룹화 후 각 그룹에 대해:

1. **언급 증권사 수** = 서로 다른 `brokerage` 개수.
   - **2 이상 → 추천 리스트에 포함.** 값이 클수록 상위.
   - 태그 `언급 N곳` + 증권사 목록.
2. **관심종목** = 워치리스트에 존재 → 언급 1곳이어도 포함, 최상단, 태그 `관심종목`.
3. **목표가 방향** — 그룹 내 어느 리포트든 제목에 `상향`/`하향`/`목표가` 포함하거나 `targetPrice` 존재 시:
   - 제목 키워드로 `목표가 상향` / `목표가 하향` 태그.
   - 직전 스냅샷(localStorage)에 같은 종목 `targetPrice` 가 있으면 변동폭(%)도 표시. 없으면 방향 태그만.
4. **신규 커버리지** — 제목에 `커버리지 개시`/`신규`/`Initiate`/`Initiation` → 태그 `신규 커버리지`.
5. **단톡방 언급** — §4.3 결과와 종목명이 겹치면 태그 `단톡방 언급`.

산업(`kind==="industry"`)·시황(`kind==="market"`)은 별도 섹션으로 목록 노출(증권사 수 집계는 하되 2곳 임계값 미적용, 정보 제공용).

### 4.3 카톡방 붙여넣기 파싱
- 입력: 자유 텍스트(여러 메시지 붙여넣기)
- 처리: 알려진 종목명 사전과 대조해 등장 종목 추출. 사전 = (a) 이번 수집에 등장한 종목 + (b) 워치리스트 + (c) 앱에 정적 파일로 동봉한 기본 종목 리스트(코스피200 + 주요 미국 종목 한글표기)
- 출력: `{ matchedStocks: string[], rawText: string }`
- 매칭 실패해도 `rawText` 는 버리지 않고 "단톡방 원문"으로 보관

### 4.4 노이즈 제거
- 언급 1곳 + 관심종목 아님 + 특이 태그(목표가/신규/단톡방) 없음 → 기본 숨김. `[전체 보기]` 로 펼침.

### 4.5 스냅샷
- 수집 성공 시 그날 결과(종목별 targetPrice 포함)를 `localStorage` 에 `snapshot:YYYY-MM-DD` 로 저장
- 목표가 변동폭 계산 시 "가장 최근의 이전 날짜" 스냅샷과 비교
- 스냅샷은 최근 14일치만 보관(초과분 삭제)

## 5. 뉴스레터 생성 & 전송

### 5.1 형식 (형식 A: 불릿)
선택된 항목을 아래 섹션 순서로 조립. 빈 섹션은 생략.

```
📈 오늘의 증권가 브리핑 · 2026년 9월 3일

[목표가·투자의견 변경]
• {종목} — {대표 코멘트} ({증권사들}, N곳)

[여러 증권사 주목]
• {종목} — {대표 코멘트} ({증권사들}, N곳)

[시황]
• {제목} — {증권사}

[신규 커버리지]
• {종목} — {대표 코멘트} ({증권사})

[단톡방 언급]
• {종목} — {요약 또는 원문 발췌}

────────
※ 자료: 네이버 금융 리서치, 한경 컨센서스
```

- **섹션 분류 규칙**: `목표가 상향/하향` 태그 → 목표가 변경 / 그 외 언급 2곳 이상 → 여러 증권사 주목 / `kind==="market"` → 시황 / `신규 커버리지` 태그 → 신규 커버리지 / 단톡방 발 → 단톡방 언급. 한 종목이 여러 조건이면 목표가 변경 > 신규 커버리지 > 여러 증권사 주목 순으로 하나에만 배치.
- **대표 코멘트**: 그룹 내에서 (a) 목표가 키워드가 있는 제목 우선, 없으면 (b) 가장 최근 리포트 제목.
- **대표 증권사 표기**: 최대 3곳 나열 후 "외" 처리 가능. 예: `삼성·미래에셋·KB 외, 5곳`.
- 텍스트는 화면 ②에서 자유 편집 가능.

### 5.2 전송
- **[전체 복사]**: 조립된(또는 편집된) 텍스트 전체를 클립보드로 복사.
- **[카톡으로 보내기]**: `navigator.share({ text })` 호출 → 공유 시트 → 카카오톡 → "나와의 채팅".
  - 미지원 환경에서는 자동으로 복사 동작 + 안내 문구.

## 6. 문제 상황 대응 & 한계

### 대응
| 상황 | 동작 |
|---|---|
| 네이버 또는 한경 수집 실패 | 성공한 출처로 진행 + "○○ 수집 실패" 배지. 둘 다 실패 시 "잠시 후 새로고침" 안내 |
| 추천 항목 0건 | "오늘은 2곳 이상 겹친 종목이 없습니다" + `[전체 보기]` 유도 |
| 카톡방 파싱서 종목 미검출 | "단톡방 원문" 섹션으로 보존, 뉴스레터에 첨부 옵션 |
| 카카오 공유 실패/미지원 | "전체 복사"로 폴백 |
| localStorage 소실 | 관심종목 내보내기/불러오기로 수동 백업 제공 |

### 한계 (문서화)
1. 네이버·한경 사이트 개편 시 파서가 깨질 수 있음 → 개발자가 수정 필요.
2. 목표가 변동폭은 직전에 앱을 연 날 대비로만 계산됨(방향 태그는 매일 가능).
3. 실시간/장중 속보는 다루지 않음. 아침 리포트·코멘트 정리가 목적.
4. 이용약관: 개인 참고용 수집 수준. 뉴스레터 유료 재판매 시 각 사이트 약관 별도 확인 필요.

## 7. 테스트 전략

### 자동 테스트 (vitest)
- **파서**: 저장해 둔 네이버·한경 HTML 픽스처 → `ResearchItem[]` 로 정확히 분해되는지 (종목명/증권사/목표가/날짜)
- **정규화/중복제거**: 증권사명 표준화, 유사 제목 병합
- **추천 규칙**: 합성 데이터로
  - 3곳 언급 종목이 리스트에 포함되고 상위 정렬
  - 1곳 + 관심종목 → 포함 + 최상단
  - 1곳 + 특이 태그 없음 → 숨김
  - 목표가/신규 커버리지 태그 부여
- **뉴스레터 조립**: 항목 N개 선택 → 섹션 분류·불릿 형식·빈 섹션 생략 검증
- **카톡방 파싱**: 샘플 텍스트에서 종목 추출

### 사용자 인수 테스트 (배포 후 3일 아침)
1. 새로고침 결과가 실제 당일 리포트와 부합하는지(오탐 없는지)
2. 관심종목 추가 → 다음 새로고침에서 최상단 노출
3. 카톡방 내용 붙여넣기 반영
4. 뉴스레터 생성 → 복사 → 평소 워크플로에 붙여넣기 → 형식 적합성
5. 카톡으로 보내기 → "나와의 채팅"에 도착

3일 피드백 취합 후 조정.
